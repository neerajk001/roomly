# V4 — Pro Mode

**Goal:** an interior designer or remodeler runs a full client workflow: create a client, send a brief link, receive photos and answers, generate branded options, build an estimate from their own rate card, send a proposal, and get client approval.

**Read first:** `AGENT.md`, `05-estimate-engine.md`, `03-auth-and-workspaces.md` (public token links), `02-database.md`.

## 1. Studio profile

- [x] `/studio/settings`: studio name (logo, brand colour, currency, units, contact, default terms), logo upload, brand color, currency, unit system, contact email/phone, default proposal terms text.
- [x] Logo stored as an `Asset` (PNG/JPEG/WebP ≤2 MB; SVG not accepted yet) (`LOGO`) and referenced by `Workspace.logoStorageKey`. Validate type and size (PNG/JPEG/SVG sanitized or rasterized; ≤2 MB).
- [x] Pro workspaces never get the platform watermark on renders.

## 2. Clients

- [x] CRUD (`name`, `email`, `phone`, `notes`), soft delete, search by name/email.
- [x] Client detail page: list of projects, brief links, proposals and statuses.
- [x] Attach a project to a client at creation or later.

## 3. Brief links (public intake)

- [x] Designer creates a brief link for a client (optional expiry). Copy link and "send by email" action.
- [x] `/brief/[token]` public page (branded with the studio logo and color):
  - Questions: room type(s), goals, style likes (pick from style images), budget range, timeline, must-keep items, notes.
  - Photo upload (up to 8 photos, same validation as V2) using token-scoped presigned uploads.
  - Honeypot field + IP and token rate limits. No account needed.
- [x] On submit: create `BriefSubmission`, a draft `Project` linked to the client, `Room` records (name from the answers; dimensions left blank to complete), `Asset` rows (`BRIEF_UPLOAD`) attached to rooms. Mark the link `SUBMITTED` (or allow multiple submissions if the designer chooses).
- [x] Email notification to the designer.

**Acceptance:** a client can complete the brief on a phone without an account; the designer sees a ready draft project with photos and answers.

## 4. Rate cards

- [x] On first Pro onboarding, create a default rate card with a starter set of items (paint walls, paint ceiling, flooring, skirting, lighting point, false ceiling, wardrobe per running metre, curtains, furniture package) at **placeholder prices clearly marked "edit me"**.
- [x] Rate card list and editor: items grouped by category, unit (area floor/ceiling/wall, perimeter length, per unit, lump sum), unit price, sort order, markup %, tax %.
- [x] Multiple rate cards (e.g. "Standard", "Premium"); one default.
- [x] CSV import and export (validate headers, show row-level errors before applying; never partially apply).
- [x] Imperial workspaces: show price per sq ft/ft, store per m²/m (see `05-estimate-engine.md`).

## 5. Estimate builder

- [x] From a room: choose a rate card → "Auto-fill from room" selects items by scope template (designer can save their own scope templates, V4 optional) → lines computed with `computeEstimate`.
- [x] Editable table: change label, quantity, unit price; add custom line; delete line; reorder. Recalculate with `recompute` from `packages/estimate`. Totals show subtotal, markup, tax, total.
- [x] Multi-room projects: one estimate per room plus a project summary total.
- [x] Save as a new **version**. Show version history with totals and dates. A version referenced by a sent proposal is read-only.
- [x] Estimate shown with exact values (no range) unless the designer turns on "show as range".

## 6. Render workflow for Pro

- [x] Same generation tools as V2/V3 but without watermark and with a "Pin to proposal" action on outputs (up to 4 options per proposal).
- [x] Designer can add a short caption per option (e.g. "Option A — warm minimal").

## 7. Proposals

- [x] Proposal builder: title, intro text, pinned render options (ordered), estimate version, terms text (defaults from studio settings), validity (expiry date).
- [x] Preview in the browser matching the final PDF.
- [x] **PDF generation** with `packages/pdf` (on-demand in the web app, not a worker job yet; text + estimate, not option images) (react-pdf): cover with logo and brand color, project and client names, options with captions, estimate table, terms, disclaimer "Renders are concept visuals and not to scale. Estimate is based on provided measurements and the rates shown." Generated by a worker job; stored in S3; `pdfStorageKey` set.
- [x] **Send**: freezes the proposal (immutable snapshot of text, options, estimate version), generates `publicToken`, status `SENT`, sends an email with the link (and the PDF link). Editing after sending creates a **new version** (v2) linked to the same project; the old link shows "superseded, see the latest" if the designer enables that.
- [x] Statuses: `DRAFT → SENT → VIEWED → APPROVED | CHANGES_REQUESTED | EXPIRED`. Status timeline on the proposal page.

## 8. Client approval page (`/p/[token]`)

- [x] Public, branded, mobile-first. Shows options as a swipeable gallery with before/after, the estimate (collapsed by default, expandable), terms, and a PDF download.
- [x] First view sets `viewedAt` and status `VIEWED` (once).
- [x] Client actions: comment (name required, message), **Approve** an option (confirm dialog, records `approvedAt`, `approvedOutputId`, name), or **Request changes** (message required).
- [x] Expired or superseded proposals show a clear message and no actions.
- [x] Designer gets an email on view (first time), comment, approval and change requests.
- [x] `noindex`, no referrer, rate limits on comments/actions, CSRF-safe actions.

**Acceptance:** end-to-end: client approves option B; designer sees APPROVED with option B and the client's name and timestamp; the approved version cannot be edited.

## 9. Designer dashboard

- [x] `/studio` home: pipeline columns by proposal status (Draft, Sent, Viewed, Approved, Changes requested) with counts and recent activity.
- [ ] Project page: tabs Rooms, Renders, Estimate, Proposals, Activity.

## 10. Tests

- [ ] Isolation tests for clients, rate cards, estimates, proposals, brief links (A cannot touch B).
- [x] Rate card CSV import: valid, invalid rows, no partial apply.
- [x] Estimate editing and versioning; immutability after send.
- [x] Proposal state machine: all valid transitions; invalid ones rejected (e.g. approve an expired proposal).
- [x] Public pages: token validity, expiry, rate limits, no data leakage, honeypot.
- [x] PDF snapshot test (render to PDF, check page count, key text present).
- [ ] Playwright: designer creates client → brief link → client submits in an incognito context → designer builds estimate → sends proposal → client approves.

## Definition of Done for V4

- [ ] All boxes ticked; CI green.
- [ ] Full workflow works with the fake provider locally and with the real provider in a manual run.
- [ ] A designer with no help can finish brief → approved proposal in under 20 minutes (record a manual timing note).
- [x] Summary for the human.

**Out of scope for V4:** invoicing, payments between designer and client, team seats, contractor handoff.
