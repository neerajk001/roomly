# V1 — Foundation: summary for review

Historical phase-completion snapshot. Features, counts and open items below describe
that review point, not current status. See [current project status](project-status.md)
for the delivered guided flow, current auth and remaining review gates.

Date: 2026-10-28 · Commits: `b7f2bb6` (tooling), `1e298f0` (database),
`c7ccdaf` (auth), `086d938` (onboarding/shells), test commit.

## What works

- **Monorepo**: pnpm + Turborepo, 9 packages + web/worker, strict TypeScript,
  ESLint/Prettier, CI workflow (Postgres service, validate, migrate, typecheck,
  lint, unit/integration tests, Playwright, build).
- **Database**: Prisma 7.10.1 with driver adapter, full app schema from
  `02-database.md`, Better Auth tables generated by the CLI, `User.mode` and
  `User.onboardedAt`, initial + onboarding migrations, seed (`--demo`).
- **Auth**: Better Auth 1.7.14 (Prisma adapter, email+password with
  verification, password reset, Google when credentials exist, rate limiting,
  `nextCookies`). `bootstrapWorkspace` creates the personal workspace, OWNER
  membership and one `SIGNUP_GRANT` row idempotently. Auth pages for sign-in,
  sign-up, verify-email, forgot/reset password. `requireSession`,
  `requireWorkspace`, `requireOnboarded`, `requireVerifiedEmail` helpers.
- **Onboarding and shells**: `/onboarding` (Home/Pro choice, PRO asks studio
  name/currency/units and converts the workspace to STUDIO), redirects to
  `/app` or `/studio`, guarded route groups, shadcn/ui tokens, app top bar,
  studio sidebar (Projects, Clients, Rate cards, Settings) with empty states,
  `/settings` (display name, mode, currency, units, sign out), placeholder
  landing page.
- **Tests**: 7 env-schema unit tests, `bootstrapWorkspace` integration test
  (idempotency + ledger), tenant-isolation scaffold (3 tests), 3 Playwright
  tests (Home path at 375 px, Pro path, unauthenticated redirect). All green
  locally; `pnpm build` passes.

## What was skipped / deferred

- Google OAuth was not exercised against real credentials (no client id/secret
  available). The provider is registered only when both env vars exist.
- CI has not run on GitHub yet (no remote). Everything was verified locally.
- Project creation, uploads, renders, estimates, proposals are V2+; the
  "New project" buttons are intentionally disabled.
- Dark-mode toggle UI is not built; tokens are ready for it.
- Mailpit SMTP is not wired; `EMAIL_PROVIDER=console` is used in dev.

## Open questions / gates
